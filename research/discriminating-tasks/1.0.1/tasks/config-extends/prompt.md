src/config.js loads a JSON config file. Add support for an `extends` key to it, following the rules below, without breaking what it already does. Run the tests with: node --test. Do not change any file under test/.

`loadConfig(file, { readFile })` returns the config object for `file`. `readFile(path)` is given in the options and returns the text of the file (it throws if the file is missing). All paths use `/` and are handled with `node:path/posix`.

Rules:
R1. A config may have an `extends` key: a string, or an array of strings, naming other config files. A name that starts with `/` is used as it is; any other name is relative to the directory of the file that contains it. Every path is normalized with `path.posix.normalize` before it is read or compared, the top-level `file` too, and `readFile` is called with the normalized path. Only a missing `extends` key means no bases. If the key is present with any other value (`null`, a number, an object, `true`, or an array that holds anything other than strings), `loadConfig` throws a `TypeError` whose message contains the path of the file it is in. An empty array is allowed and means no bases.
R2. The result is built by starting with an empty object, merging each base file's result in the order listed (a later one overrides an earlier one), and then merging the file's own keys on top. A base file's own `extends` is resolved the same way, so the process is recursive. The `extends` key itself is not part of the result.
R3. Merging: when both sides of a key are plain objects (not arrays, not `null`) they are merged key by key with the same rules; in every other case the later value replaces the earlier one completely. Arrays are replaced, not joined, and a later `null` replaces an earlier value.
R4. A file that, directly or through its bases, extends itself makes `loadConfig` throw a `RangeError` whose message contains `cycle` and the chain of normalized paths joined with ` -> `, ending with the path that closed the loop (for example `cycle: /a.json -> /b.json -> /a.json`). Reaching the same file twice by different routes (a diamond) is not a cycle.
R5. A file whose text is not valid JSON throws a `SyntaxError` whose message contains that file's path. A file whose JSON is not an object (an array, a string, `null`, and so on) throws a `TypeError` whose message contains its path, as before. This applies to base files too. An error thrown by `readFile` is passed on unchanged.
R6. Each file is read at most once in one call to `loadConfig`, even if several files extend it.
R7. A key named `__proto__` in a JSON file is an ordinary key: it is kept as an own property of the result, at any depth, and is merged like any other key (R3). Loading never changes `Object.prototype` or any other prototype, and the result and every object inside it still have `Object.prototype` as their prototype.
