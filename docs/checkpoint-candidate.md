# Verified initial-state checkpoint candidate (source-tree PR A)

`endo.checkpoint-candidate.v0` is a receipt for one boundary: the pre-execution scratch tree of a recorded Pi cassette session. It is written only after `endo replay` has restored that tree at its recorded absolute path, run a fresh Pi against the cassette and completed the authoritative trajectory comparison. The reader is `readVerifiedCheckpointCandidateV0(source, replay, key)`; the file is `<replay-store>/replay-artifacts/checkpoint-candidate.json`. It never changes the source store or `endo.replay-report.v0`.

The qualification path re-reads the source and replay capture logs. It rejects torn or corrupt tails in either capture or session event log; a readable valid prefix is insufficient. It checks the same keyed source capture generation that was read before replay, the source trajectory generation, the recorded archive reference and keyed blob, the archive's canonical v1 schema, and replay capture context. It requires each recorded exchange to be served once, no misses, no unserved exchange, matching driver steps and reached STOP, kill or intervention points. A reached point must have its recorded chunk in both the cassette and the replay's served count; finishing an exchange before a requested point does not count as reaching it. Settlement must be observed, and each persisted intervention result must be accepted on both recording and replay; matching refusals do not qualify. The comparison is recomputed from the two stores; lifecycle, tool calls, tool results and outcome must each be `EXACT`, with no disqualifying flags. The receipt records keyed archive, capture and environment commitments and the comparison identities. A reader rechecks these facts against the current stores and refuses stale or changed evidence. Keyed digests are commitments within a digest domain, not signatures or proof of who produced the data.

The archive contains scratch file bytes, entry kinds, executable flags and modification times. It does not contain owner/group, all permission bits, a process, a model's internal state or a live tool invocation. The receipt has no workspace bytes, prompts, model responses, credentials or raw paths. An `EXACT` cassette replay proves observed equivalence under the captured model responses and this initial scratch state. It does **not** prove that the complete external environment can be reconstructed. External files, services, sockets, devices, clock, randomness and side effects can agree by coincidence or remain unseen. An outward scratch symlink is refused because its target is not in the archive.

General mid-run checkpoints remain unavailable: there is no capture of a paused Pi process, in-flight tool state, provider state, external effects or an executable continuation point. Cassette-then-live would need an explicit, validated switch boundary and a live model authority with configuration and request identity. Branching would additionally need isolated state per child, parent checkpoint identity, the changed variable, and lineage tying each continuation to its own trajectory and environment. DSH's import checkpoint marks an evidence boundary; it is not a restorable execution checkpoint.

This is a source-tree implementation. Published npm `0.1.0-alpha.1` and `0.1.0-alpha.2` do not contain it.
