# Limits of B–D

- The first-attach E4 path is implemented and exercised through the storage API by separate OS processes and CLI explicit init. It is **not wired end to end**. `adapters/pi/attachment.ts` (`PiAttachmentV0.identify`, `PiSessionAttachmentV0` construction), `adapters/codex/develop-adapter.ts` (`open`), `cli/commands.ts` (`ingestCommand`), `cli/dsh.ts` (`dshImportCommand`), and `cli/cassette-fixture.ts` (`materializePiCassetteFixtureV0`) still select the old path. Ingest and DSH now guard and lock it; they do not fall back to E4 streams. These are routing sites for E, not competing implementations of the new format decision.
- E must move format resolution before other writes, including Pi identify/registry and persistent config, Codex checks, harness CLI registry, direct legacy event-store/lock opens, cassette fixtures and any DEVELOP-first entry points that intend to create E4 state. Apply C31's fs-preload mutation trace per adopted entry point. Restate the initial-child sentinel cleanup assertion only when that fixture actually writes E4. Standalone harness-registry, capture writer exclusivity and the control socket are not migrated here.
- F still owns projections, coordinator v1, Studio routes and write-independent push delivery, sandbox pinning, scheduler counters and replay. Old readers cannot be relied on to disclose attachment streams. Do not use this B–D binary to migrate a production root and then continue normal adapter execution there.
- The resume test proves deterministic cursor/id seeding at the storage boundary, not installed Pi or Codex resume. Nothing here demonstrates scheduled agents, live heterogeneous dispatch, model inference, or operational acceptance.
- The format contract assumes cooperative local POSIX users and a writable parent for staging the complete initialisation directory; NFS, arbitrary FUSE, hostile ancestor replacement and noncooperative writers are not fenced. A crashed process may leave same-filesystem scratch staging beside the root. A lost sentinel in the brief window before any witness or stream exists leaves no format evidence for a reader to rediscover. Once any survives, its loss is detectable. A witness missing after a valid sentinel may be completed; the sentinel may not.
- Verification of a sibling snapshot never proves it was simultaneous with another. Discovery is bounded and the absence of a visible event is not an exclusion of its route. Foreign ownership checks cover recognised qualified Pi and Codex producers; arbitrary producer strings do not prove ownership. The duplicate reporting tie-break is presentation order, never physical writer chronology.
- A drift report distinguishes observed and sealed size/hash; it doesn't enumerate quarantine files or count an unverified suffix as events. The fixture tests changed bytes on isolated roots; no claim is made about power-loss mechanics beyond the specified POSIX assumptions. Migration truly requires every old unlocked process to be stopped.
