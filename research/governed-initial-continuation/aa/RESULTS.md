## Implementation and present limitations

`study-plan.ts` exclusively creates a private keyed plan and rereads the current qualified parent and pristine sibling set. It fixes a small one-digit addition task and reference prompt, requires equal supported condition declarations with distinct IDs, binds both preflight templates, seed-derived ABBA/BAAB order and bounded budgets. Server configuration is currently an operator **declaration**, not an independently verified observation. The key provides local integrity, not a signature or authentication of a human. Timestamps provide bounded local ordering evidence, not a trusted external clock.

`coordinator.ts` is a research building block, not a live operator command. It records an exclusive slot before accepting separate approval callbacks, calls the existing two-turn executor and receipt verifier, and stops subsequent slots after a decline or uncertain/incomplete result. Its callbacks are trusted caller inputs and cannot establish a human approval or independently verify a server. Tests alone supply synthetic callbacks. A real operator-facing command must use terminal-directed input, cancel stale input on timeout or interruption, and connect an independently rechecked environment/resource observer before this can be used live.

`reader.ts` independently rechecks current plan, lineage and each completed continuation receipt before measuring captured requests and responses. It refuses duplicate attempt/session identities, reordered or incomplete slots, mismatched conditions, plans, effective request parameters and common context. It checks the task answer separately from structural validity. It compares exact captured **request-body** digests; full request-wire bytes are unavailable. A diagnostic context comparison replaces only one uniquely located `<cwd>` system-field value grounded in the verified runtime directory, rejects marker collisions and retains raw context digests. Response wire comparisons concern retained wire, whose headers may have been scrubbed. Reasoning bytes and presence are measured without publishing content. `read-private.ts` is a fresh-process entry point that exclusively writes a private result; its `four-receipts` status deliberately leaves server identity unverified and is not an A/A PASS.

The offline tests exercise the new coordinator and reader in both orders, with deliberately wrong fake answers accepted structurally but rejected by the scorer. They cover plan tampering, unequal declarations, slot tampering, unplanned slots, both approval denials and cwd marker collisions. These controls are not the complete adversarial acceptance suite listed below. No real inference is included in CI.

Complete the private plan before dispatch: exact prompts and deterministic expected token, seed and selected ABBA or BAAB sequence, qualified parent and freshly prepared matched sibling identities, full budgets and explicit server observations. Bind each attempt to its position and plan without publishing private prompts or keys. Record an initial source/sibling verification and verify them again after the study.
2. Complete the bounded sequential coordinator and operator command using the existing continuation runner and requires the operator to enter both exact phrases for every attempt. Verify each closed receipt and owned-resource cleanup before continuing; stop on uncertainty, failed parity or feasibility gate. Never retry a dispatched attempt. The first pair is a feasibility gate, not permission to skip later approvals.
3. Harden the independent read-only comparison process so it re-verifies each receipt against current source and siblings, rejects duplicate attempt/session IDs, incorrect order or role, changed generation, condition, prompts, model, executable and budgets, and checks effective request parameters and no-tool surface. Verify model file, server process and configuration separately; receipt validity alone cannot establish those facts. Capture omissions explicitly.
4. Complete bounded private measurements from verified captures: exact request hashes and lengths, responses and task scores, usage and cached-token reports, reasoning presence/length and clock boundaries. Compare second requests by common structure and within-session retention rather than demanding identical bytes. Normalize cwd only where the particular field and replacement are uniquely identified and independently grounded; preserve raw equality and classify all other differences. Produce a separately redacted report.
5. Exercise the complete workflow with fake Pi and endpoint, including stale or tampered source, siblings, receipts and transcript; duplicates, unequal conditions and models; prompt/tool changes and extra dispatch; missing approval; disconnected, partial, timeout and unknown outcomes; unsupported framing or reasoning; and a wrong answer in a valid receipt. Confirm cleanup affects only owned resources. The feasibility test here is not a substitute for these controls.
6. Revalidate Pi, model file, loopback endpoint, server settings and GPU resources. Starting a task-owned server requires the operator's explicit approval. Each turn needs its own exact operator-entered phrase. If an outcome is unknown after dispatch, stop and preserve evidence; do not rerun it. A verified first pair without a second pair is a feasibility result, not a completed study.

A future A/A PASS must mean the preregistered governed procedure completed and was independently verified, not that all answers match. With two sessions per arm, report descriptive observations only. Shared server state, order, GPU load, caching, omitted sampling parameters and fresh process/RNG/KV state limit interpretation. Identical answers do not establish determinism; differing answers do not establish an effect of sibling identity; reported cached tokens do not prove cache savings.

No A/B treatment is supported by this feasibility test. Once a valid A/A baseline exists, a candidate smallest next study is a separately preregistered change to one supported sampling parameter, provided both the runtime and the independent reader can verify its effective value; the current governed condition surface does not yet support that manipulation.
